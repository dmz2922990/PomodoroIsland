多 Agent 并发通知：岛屿堆叠展示

## 目标

多个 agent 同时有待处理通知时，岛屿纵向堆叠显示全部卡片，每张卡可直接作答；交互式（ask_user/权限）排前、先到在前；被动通知折叠为紧凑行。消除"新通知抢占显示位埋掉待回答卡片"的问题。

## 现状关键事实

- 数据层已支持多条并存（pending 数组，上限 3 交互/全局、2 交互/来源、5 被动），展示层只渲染 `pending.first` 一张
- `insert(at: 0)` 新者抢占显示位，旧交互卡被隐藏但超时倒计时继续
- 高度机制（HeightProbe → controller.notificationContentHeight → setFrame）只测量单卡，且已跨翻转持久（上次修复）

## 改动

### 1. `Model/NotificationStore.swift`
- 新增计算属性 `displayOrder: [IslandNotification]`：交互式按 creation 升序（先到在前）+ 被动按 creation 降序（新的紧跟其后，旧的在底部即将自动消失）
- submit/insert/结算逻辑不动（insert at 0 保留，仅展示顺序由 displayOrder 决定）
- `current` 保留（仅作"有无通知"判断用，IslandStripView 指示点等）

### 2. `UI/NotchRootView.swift`（NotificationIslandView 重写）
- `ForEach(displayOrder)` 渲染卡片栈：交互式 = 完整 NotificationCardView（保留各自 multiSelected/inputText 状态，ForEach by id）；卡片间 8pt 间距 + 发丝分隔线
- 被动通知 = 紧凑单行（来源点 + 标题截断 + ✕ 提前关闭），不占大高度——被动本就数秒自动消失
- 每张交互卡独立 HeightProbe → controller 新增 `@Published cardHeights: [UUID: CGFloat]` 字典
- **屏高溢出保护**（一台屏 900~1080pt 逻辑高度时 3 张高卡可能放不下）：可用高 = 屏幕可视高 - 刘海带 - 边距；从上往下累计卡片实测高，放不下的卡片及以下全部渲染为一行「+N 更多排队（来源+标题）」；紧凑行高按固定 36pt 估算——单遍确定性计算，不依赖二次测量
- 总高度 = 各渲染块之和 + 间距，走现有 `notificationHeightChanged` 上报，窗口 setFrame 机制不变
- 动画锚点从 `current?.id` 改为 `pending.map(\.id)`（栈成员变化才触发切换动画）

### 3. `Notch/NotchWindowController.swift`
- 新增 `cardHeights` 字典（@Published，跨翻转持久，与 notificationContentHeight 同理）
- `notificationContentHeight` / `notificationFrame` / 无动画展开逻辑均不变

### 4. 不改动
- MCP 协议与 submit 上限（多 agent 并发控制已存在）
- hook 脚本、settle 收起逻辑、shouldStayOpen

### 5. 验证
- `swift build && make-app.sh`，重启应用
- 多 agent 场景实测（curl 模拟）：zcode 权限卡 + claude 提问卡（先发）+ codex 提问卡（后发）+ 2 条被动通知 → 截图确认：交互卡先到在前、被动紧凑行在底、每张卡完整可操作、总高度自适应
- 点击第 2 张卡的选项作答 → 该卡结算消失、其余不动、高度收缩
- 超时兜底：等待某张超时 → 结算后栈收缩
- 回归：单通知场景显示与之前一致（完整卡片）
